1. Introduction

Dans le cadre du projet de tri intelligent de déchets à TEKBOT CITY, cette section détaille la conception de la partie électronique du système de convoyeur. Elle vise à permettre à toute personne, même novice, de comprendre la démarche, de la conception initiale jusqu'à l'implémentation finale du système embarqué. Le système développé combine plusieurs technologies pour créer un convoyeur intelligent capable de détecter automatiquement la présence de déchets, d'analyser leur couleur et de transmettre ces informations via WiFi. Cette documentation couvre l'ensemble du processus de conception électronique, depuis le choix des composants jusqu'à la réalisation finale.

2. Objectifs Techniques

  • Détection de présence : Utilisation de capteurs LDR couplés à des lasers pour détecter l'arrivée et le positionnement des déchets.
  • Analyse colorimétrique : Identification précise des couleurs avec le capteur TCS3200.
  • Contrôle moteur : Pilotage du convoyeur via relais pour moteur DC.
  • Sécurité : Intégration d'un bouton d'arrêt d'urgence.
  • Communication sans fil : Transmission des données via ESP-01 et WiFi.
  • Autonomie : Système alimenté par batterie Lithium avec régulation stable.
  • Feedback visuel : LEDs indicatrices pour chaque couleur détectée.

Partie 2 : Évolution vers la Détection par Vision Intelligente (IA)

13. Introduction à l'Évolution du Projet

La première version de notre système de tri a rempli avec succès ses objectifs initiaux, en utilisant un capteur TCS3200 pour discriminer les couleurs. Cependant, cette approche présentait des limitations inhérentes :

  • Sensibilité : Le TCS3200 est sensible à la distance, à l'éclairage ambiant et ne peut analyser qu'une petite zone à la fois.
  • Manque de flexibilité : Il ne peut identifier que des couleurs pures et ne peut pas faire la différence entre un "cube rouge" et un "bouchon rouge". Le système ne reconnaît pas la forme ou le type d'objet.
  • Extensibilité limitée : Ajouter la détection de nouveaux types de déchets complexes (ex: canettes, bouteilles en plastique) est impossible.

Pour surmonter ces défis et rendre notre système véritablement "intelligent", nous avons fait évoluer le projet en remplaçant le module de détection par une solution de vision par ordinateur basée sur l'IA. Cette mise à niveau utilise une caméra ESP32-CAM et un modèle de détection d'objets YOLOv8, transformant notre convoyeur en une plateforme de tri beaucoup plus puissante.

14. Nouveaux Objectifs Techniques (V2.0)

Cette évolution vise les objectifs améliorés suivants :

  • Détection d'Objets par IA : Remplacer l'analyse colorimétrique par une identification d'objets ET de couleurs via un modèle de deep learning (ex: "cube_rouge").
  • Robustesse Accrue : Être moins sensible aux variations d'éclairage et au positionnement exact du déchet.
  • Architecture Matérielle Simplifiée : Remplacer le couple TCS3200 + ESP-01 par un unique module ESP32-CAM.
  • Flexibilité Maximale : Permettre d'ajouter de nouveaux types de déchets en ré-entraînant simplement le modèle logiciel, sans modification matérielle.

16. Développement du Modèle de Détection d'Objets (YOLOv8)

Cette section est un guide détaillé de la procédure suivie pour créer le "cerveau" de notre système. L'objectif est de produire un modèle de détection d'objets capable de fonctionner sur un microcontrôleur.

16.1. Outils et Philosophie

  • Roboflow : Utilisé pour centraliser, annoter et gérer notre jeu de données. C'est un outil essentiel pour un flux de travail MLOps propre.
  • Kaggle : Plateforme choisie pour l'entraînement grâce à l'accès gratuit à des GPU puissants, indispensables pour accélérer le processus.
  • YOLOv8 : Architecture de modèle sélectionnée pour son excellent compromis entre vitesse et précision, idéale pour des applications temps réel.

16.2. Étape A : Création du Jeu de Données sur Roboflow

La qualité du modèle dépend de la qualité des données. Voici les sous-étapes :

  1. Collecte d'images : Prise de photos de nos objets (cubes de couleurs) sous différents angles, éclairages et fonds et complétés avec des images en ligne.
  2. Annotation : Dans l'interface Roboflow, chaque objet sur chaque image a été manuellement encadré par une "bounding box", et la classe correspondante (ex: `cube_rouge`) lui a été assignée.
  3. Génération de Version : Une version du dataset a été générée. Nous avons appliqué des augmentations (rotation, bruit, variation de luminosité) pour rendre le modèle plus robuste et avons réparti les données : 70% pour l'entraînement, 20% pour la validation, 10% pour le test.
  4. Exportation : Le jeu de données a été exporté au format YOLOv8. Roboflow fournit alors un snippet de code à usage unique pour télécharger ce dataset directement dans un environnement comme Kaggle.

16.3. Étape B : Entraînement du Modèle sur Kaggle

Une fois le jeu de données prêt, nous sommes passés à l'entraînement :

  1. Configuration du Notebook : Création d'un notebook Kaggle avec un accélérateur GPU (T4 ou P100) activé.
  2. Installation des dépendances : Installation de la bibliothèque `ultralytics` qui contient YOLOv8, via `pip install ultralytics`.
  3. Lancement de l'entraînement : La commande suivante a été exécutée. Elle utilise l'apprentissage par transfert (partir d'un modèle déjà entraîné) pour accélérer la convergence.
# Explication de la commande :
# task=detect: Nous faisons de la détection d'objets.
# mode=train: Nous sommes en mode entraînement.
# model=yolov8s.pt: 's' pour 'small'. Un modèle léger, parfait pour commencer.
# data=.../data.yaml: Le chemin vers le fichier de configuration de notre dataset (fourni par Roboflow).
# epochs=50: Le modèle verra l'ensemble du jeu de données 50 fois.
# imgsz=320: Toutes les images sont redimensionnées en 320x320 pixels, une taille adaptée à l'ESP32-CAM.

!yolo task=detect mode=train model=yolov8s.pt data=dataset.location/data.yaml epochs=50 imgsz=320 plots=True

17. Nouvelle Architecture Logicielle (V2.0 - Déploiement Cloud)

Pour maximiser la flexibilité et la performance, nous avons opté pour une architecture d'inférence cloud. Au lieu de faire tourner le modèle sur l'ESP32-CAM (on-device), nous le déployons sur les serveurs de Roboflow. L'ESP32-CAM agit alors comme un client qui envoie une image et reçoit le résultat.

17.1. Étape A : Déploiement du Modèle sur Roboflow

Après avoir entraîné notre modèle (fichier `best.pt`), nous ne l'exportons pas en `.tflite`. À la place, nous le téléversons sur Roboflow pour le déployer comme une API.

  1. Upload des Poids : Dans notre projet Roboflow, nous utilisons la section "Upload" pour téléverser le fichier `runs/detect/train/weights/best.pt` généré par Kaggle.
  2. Déploiement en API : Une fois le modèle enregistré sur Roboflow, il peut être déployé. Roboflow fournit alors des informations cruciales pour son utilisation.

17.2. Cerveau de Vision : Code de l'ESP32-CAM (Client API)

Le rôle de l'ESP32-CAM change radicalement. Ses bibliothèques clés deviennent `WiFiClientSecure` et `Arduino_JSON`.

17.3. Contrôleur Matériel : Code de l'ATMega (Stable)

Le code de l'ATMega ne change presque pas. Il est complètement découplé de la complexité de l'IA.

18. Nouvelle Séquence de Fonctionnement

  1. Un déchet arrive (détecté par LDR1). L'ATMega démarre le convoyeur.
  2. Le déchet arrive sous la caméra (détecté par LDR2). L'ATMega arrête le convoyeur et déclenche l'ESP32-CAM.
  3. L'ESP32-CAM capture une image et exécute le modèle YOLOv8.
  4. Il identifie la classe de l'objet (ex: "cube_rouge").
  5. Il envoie cette classe à l'ATMega et les données complètes au serveur.
  6. L'ATMega reçoit la classe, allume la LED correspondante et actionne le bon mécanisme de tri.
  7. Le système est prêt pour le prochain déchet.
